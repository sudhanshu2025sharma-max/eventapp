# 1. Push notification issue

The session reminder and push notification feature is implemented correctly in the code, but it is currently failing at the deployment/network layer on the IITD VM. We have clear evidence that the reminder logic runs successfully: the command python3 manage.py send_session_reminders logs messages such as 5-min all-users reminder sent: [TEST] Reminder Test — starts in 6 min and Bookmark reminder sent: akshita.singh@test.com → [TEST] Reminder Test — starts in 6 min, which proves session detection, bookmark matching, and device token lookup are all working. We also confirmed active Expo device tokens exist in the database for users like akshita.singh@test.com. However, delivery fails because the VM cannot establish a valid outbound HTTPS connection to Expo’s push server (https://exp.host/--/api/v2/push/send). The backend logs show repeated errors such as ProxyError('Unable to connect to proxy', OSError('Tunnel connection failed: 302 Moved Temporarily')) and later ConnectTimeoutError ... Connection to exp.host timed out, proving that IITD’s proxy/network is blocking Expo Push API access. Additional tests confirm this is a network restriction, not an application bug: https://fcm.googleapis.com is reachable from the VM, while Expo HTTPS access is blocked, so push generation works but push delivery cannot leave the server.
